# LingCast Next 直播互动采集

Chrome 120 或以上。在 `chrome://extensions` 启用开发者模式，选择「加载已解压的扩展程序」，打开本目录。

1. 在 LingCast Next 后台开始直播，复制该场的会话 ID 和采集密钥。
2. 打开与会话平台一致的直播间标签页。抖音支持 `https://live.douyin.com/<数字房间号>`。小红书支持 `https://www.xiaohongshu.com/livestream/<数字房间号>` 及其 `dynpath…` 路径。
3. 打开插件，填写 LingCast 服务器地址、会话 ID、采集密钥及平台，点击「开始采集」并授权访问配置的服务器。远程服务器使用 HTTPS。
4. 点击「停止采集」结束插件监听。刷新或关闭直播标签页也会停止采集。再次开始时，重新填写本场密钥。

插件从当前标签页的可见直播消息读取昵称、正文和有明确标记的进场、点赞与礼物。礼物需要能看见送礼文案、礼物名称及数量。启动后，互动区域首次出现时已有的消息会作为基线跳过。页面结构未知或字段缺失时，解析器跳过对应行。

采集数据仅上报配置的 LingCast 服务器 `POST /api/collector/events`。浏览器会话内存保留活跃采集密钥，停止后清除。队列最多保留 100 条待取消息，另可有一个最多 20 条的待确认批次。短暂网络故障以原事件 ID 重试，过期或拥堵计数显示在插件内。单次上传等待最多 25 秒。后端逐条处理评论并可能同步等待模型回复，模型或网络慢时整批可能超时。部分接收的响应只提供接收总数，插件据此显示计数。超时移出队列的批次可能已有部分事件在服务端处置。

## 验证

```sh
npm ci --prefix extensions/chrome
node --test extensions/chrome/tests/*.test.mjs
```

测试使用两套合成页面和模拟 Chrome 消息接口。小红书 DOM 选择器以旧版插件为起点。抖音的弹幕行、显示文本和昵称选择器参考了公开的 DOM 清理脚本。[Douyin Live Cleaner 源代码](https://greasyfork.org/zh-CN/scripts/570262-douyin-live-cleaner/code)

两个平台的实际直播页选择器、活动通知布局和 Chrome 装载流程待实测。验收时分别确认历史消息不会触发新任务，新评论能够上报，仅在可见通知明确包含昵称和礼物名称、数量时上报礼物。再验证切换直播间、停止采集和轮换密钥。
