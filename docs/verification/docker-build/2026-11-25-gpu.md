The adapter always uses `text_frontend=False`; a narrowly checked build patch now disables optional ttsfrd/wetext initialization while preserving tokenization and reference-audio ONNX processing. A regression test parses the actual pinned source and checks that the constructor cannot import either optional downloader. It fails against the missing patch and passes after implementation.
- Rebuilt/restarted TTS with the patch; startup logs contain no wetext/ModelScope request. Subsequent synthesis completed 4.76 seconds of audio, first chunk 1.79 seconds, elapsed 3.17 seconds.

Output was finite, decoded shape `[1, 256, 256, 3]`, elapsed including model loading 8.67 seconds. This checks real CUDA operators/model compatibility, not human lip synchronization.
